# Provenance of this benchmark run

Unlike `ml/results/benchmark.json` and `ml/results_independent/benchmark.json`
(both generated by an agent running `evaluate.py` directly against the
from-scratch checkpoint in this repo), **this file was not generated in this
build environment.** It was run by the repo owner on their own Mac against
the real Qwen2.5-1.5B-Instruct LoRA fine-tune, whose weights live only on
that machine — this build environment has no Hugging Face Hub access and
cannot hold or run that checkpoint.

`benchmark.json` in this directory is the exact, unedited output of:

```bash
cd ml
python3 evaluate.py \
  --gold ../data/independent_gold/independent_gold.jsonl \
  --checkpoint ./checkpoints/sugarshield-qwen2.5-1.5b \
  --data_scripts_dir ../data/scripts \
  --results_dir ./results_qwen_independent \
  --device mps \
  --max_new_tokens 128
```

Run details (from the terminal output, reproduced verbatim):
- `Checkpoint loaded in 30.2s on device=mps` — confirms it ran on Apple
  Silicon GPU, not a silent CPU fallback.
- 132/132 records scored; 3 produced invalid JSON (`indep_038`, `indep_051`,
  `indep_131`) and were excluded from `finetuned_model`'s accuracy/precision/
  recall (counted in `n_invalid_json`), same convention as every other
  benchmark file in this repo.
- Total wall-clock: ~602s (~4.1–6.5s/sample on MPS), consistent with the
  MPS performance fix documented in the README's "Qwen2.5-1.5B track"
  section (no repeat of the earlier 25+ minute CPU-fallback hang).
- `sample_predictions.json` was also written by this run but was not
  captured (only the final `benchmark.json` JSON was printed to the
  terminal and relayed back) — if it's needed for spot-checking individual
  predictions, re-run the command above; it's deterministic given the same
  checkpoint and gold file, aside from ordinary floating-point/timing noise.

No numbers in `benchmark.json` were edited, rounded further, or
interpreted before being committed — they're copied exactly as the script
printed them.
